**How the schematics are made.** They are generated by scripts in `gen/` (`python3 -I gen/build_a.py`, `gen/build_b.py`):
- Each sheet is a set of functional blocks.
- Every part pin gets a short wire and a net label. Nets used on more than one sheet get global labels.
- A design note under each block cites the datasheet section that each value comes from.

**Checks run on every build:**
- ERC.
- Export of the KiCad netlist and comparison against the intended connections, pin by pin (that's what "0 mismatches" means).
- A list of single-pin nets: all of them are deliberate no-connects.
- A differential-pair polarity check (`tools/netreport.py --pairs`).

## 3. Changes since checkpoint 1 (please review)

1. **RTC: HT8563 -> Gatemode BM8563** (C269877, 43 k in stock).
   - The HT8563 datasheet specifies a push-pull CLKOUT (VOH given). At 3.3 V that would drive and back-power the 1.8 V AP6275P LPO input.
   - The BM8563 has an open-drain CLKOUT (pin table), pulled up to VCC_1V8_S3. Its CLKOUT_control register resets to 32.768 kHz enabled (register reset table), so Wi-Fi gets its sleep clock without software.
   - The NXP PCF8563T is stocked, but no datasheet could be fetched (nxp.com is blocked from here, JLC has none).
2. **AP6275P VDDIO now on VCC_1V8_S3** (VCCIO_FLASH), not VCC_1V8_S0. Otherwise Wi-Fi/BT could not stay up in suspend. This is what the Khadas Edge2 reference does.
3. **Wi-Fi crystal: HELE X3S037400BA1H-Z (CL 10 pF) -> Hosonic E3SB37E0X0004E** (CL 16 pF, +-10/+-10 ppm). AP6275P s.7 asks for CL 18 pF and +-10/+-10 ppm.
4. **NTC cutoff now acts on CELL_BATPRESZ** (not ILIM_HIZ, which would also cut system power). It is gated by CHRG_OK, so it only acts while an adapter is present: a hot or cold battery can still run the device on battery. The comparator supply is switched off on battery, so it draws no current then.
5. **SD power**: kept exactly as on the Radxa IO board: optional P-FET on SD_PWR_ON not fitted, 0 Ohm bypass fitted. Radxa's device tree therefore works unchanged.
6. **Connectors with datasheets replaced ones without:**
   - nano-SIM: JXTCONN (no datasheet) -> GCT SIM8066-6-1-14-01-A (push-push, card detect).
   - microSD: SHOU HAN (no datasheet) -> Hirose DM3AT-SF-PEJM5 (KiCad footprint exists).
7. **New picks:**
   - USB-A: HOAUC HYCW236-USBA04-289B mid-mount for a 1.2 mm PCB, 4.33 mm above the board.
   - CAM-B: BXCONN FC-10A15P11H20 (1.0 mm, 15-pin, flip-lock, 2.0 mm tall).
   - Display: HDGC 0520-HX-30PWB (double-sided contacts).
8. **Digitizer port** (decision Q1) now has its pins: hub port 4, I2C6, DIG_INT# = GPIO4_A1, DIG_RST# = GPIO4_A2. Same 12-pin FFC part as the keyboard. 3.3 V switched by hub PRTPWR4.
9. **Board B isolation.** The keyboard shares I2C6 with the touch panel. BSS138 isolators on SDA, SCL, INT, RESET and BOOT keep an unpowered keyboard board from clamping the bus or being back-powered. Same technique BBQ20KBD uses for its 1.8 V trackpad.
10. **Status and LTE LEDs are red.** A green LED (Vf ~3 V) would hardly light from a 3.3 V GPIO.

## 7. Engineering risks I want you to see (not hidden)

1. **CM5 supply current per DF40 contact.**
   - At the CM5's 12 W maximum: 12 W / 4.84 V = 2.5 A across 6 VCC_SYSIN contacts = 0.41 A per contact. The DF40 rating is 0.3 A per contact (Hirose spec via JLC).
   - The Radxa IO board uses the same 6 pins at 4-5 V, i.e. up to 0.5 A per contact.
   - Typical draw (8 W) is 0.28 A per contact. Flagged for expert review.
2. **LTE supply.** The TPS63020 gives about 2 A in boost mode, against Quectel's generic 3 A / 4 A guideline (the module datasheet's max listed draw is 1.07 A). 2 x 220 uF POSCAP carry the bursts. (Already noted at checkpoint 1.)
3. **USB-A bulk capacitance**: 2 x 22 uF per port instead of USB 2.0's 120 uF, to save space. Port current is hard-limited, but hot-plug droop on the other port is not verified.
4. **Battery-path losses at worst case** (9.8 A): RSR 10 mOhm 1 W, gauge shunt 0.4 W, BATFET ~0.7 W, connector. All parts are rated for it, but layout copper and thermal design matter (checkpoint 4).
